# Разработка

## Состав

- `index.ts` — серверная точка входа.
- `runtime.mjs` — подключения, права сессий, выдача MCP сабагентам.
- `rules.mjs` — правила разрешений.
- `rpc.ts`, `mcp-rpc.ts` — RPC-контракт и его обработчики.
- `gui/` — окно, плашка, локализация и состояние.
- `test/` — unit-тесты и браузерная песочница компонента.
- `dist/` — локально собранный GUI; не хранится в Git. Для сборки выполните `npm ci && npm run build`.

## Проверка перед публикацией

Запустите `npm test`, `npm run check` и `npm run build`. Проверьте состав через `git status --short`: credentials и конфигурации пользователя не должны попадать в коммит.

Для чистой установки клонируйте репозиторий в другой каталог, выполните `npm ci` и `npm run build`. Затем проверьте наличие `dist/gui-experimental.cjs`. Подключение к Desktop описано в README; не меняйте пользовательский конфиг ради проверки чистой сборки.

Проверка wheel должна использовать настоящее событие колеса браузера. Присваивание `scrollTop` подтверждает только наличие overflow, но не работу события внутри модального окна. Песочница запускается командой `npm run test:gui`.

Изолированный интеграционный тест запускает OpenCode, локальный MCP fixture и локальный провайдер. Внешние MCP и платные модели не используются:

```sh
node test/integration.mjs codemode
node test/integration.mjs direct
```

`OPENCODE_TEST_BIN` задаёт путь к OpenCode (по умолчанию `opencode` из PATH), `OPENCODE_TEST_TMP` — родительский временный каталог. Проверяются выключение проектных серверов по умолчанию, изоляция двух сессий, явная выдача MCP ребёнку, пересечение префиксов и отключение после освобождения последним держателем.

## GitHub CLI

`bin/gh` — обёртка для владельца репозитория. Нужны Ruby и установленный GitHub CLI. Перед каждым вызовом она проверяет аккаунт `serge-masiutin` и задаёт репозиторий `serge-masiutin/opencode-session-mcp`. Установке плагина обёртка не нужна.

```sh
bin/gh api user --jq .login
bin/gh repo view --json nameWithOwner,url
```

Credentials находятся в `gh/hosts.yml` внутри общего Git-каталога, не в рабочем дереве. Права каталога — `700`, файла — `600`. Обёртка использует проектный `GH_TOKEN`, не переключая общий Keychain. `auth login`, `logout` и `switch` через неё запрещены.

В новом клоне credentials нужно настроить отдельно. Не копируйте их в публичный репозиторий и не выводите в журнал команд. Git identity, SSH и подпись коммитов также задавайте только в локальном `.git/config`.
