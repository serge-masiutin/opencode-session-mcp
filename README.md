# OpenCode Session MCP

Включайте MCP-серверы только для той сессии OpenCode, которой они нужны. Плагин добавляет окно `/mcp-session`: другие сессии не получают инструменты и инструкции выбранных серверов, даже если работают в той же папке. Встроенный `/mcp` управляет общим подключением папки; этот плагин дополнительно управляет видимостью для сессии.

- **Выключено по умолчанию.** Плагин отключает серверы и из глобального, и из проектного конфига, включая копии в worktree.
- **Отдельный выбор для сабагентов.** Агент передаёт нужный набор через `mcp_subagents`; без выбора сабагент MCP не получает.
- **Подключение без лишних процессов.** Несколько сессий одной папки используют одно подключение. Когда последняя из учтённых сессий выключает сервер, плагин отключает его в папке.
- **Окно Desktop.** Поиск, счётчик, компактный список, повтор подключения и начало OAuth-входа. Колесо прокручивает список над строками, а поиск остаётся на месте.

Пример работы:

```text
Сессия A: /mcp-session → включить context7
Сессия B: context7 не виден
Агент A:  mcp_subagents({ servers: ["context7"] })
Следующий сабагент A: context7 доступен
Агент A:  mcp_subagents({ servers: [] })
Следующие сабагенты A: без MCP
```

## Установка

Нужны Git, Node.js с npm и **OpenCode Desktop 2.2.0**. Плагин использует SDK 2.2.0 и экспериментальный GUI API. Совместимость с другими версиями не заявляется; браузерная проверка новой прокрутки выполнена в песочнице компонента, не в установленном окне Desktop.

1. Склонируйте проект и соберите окно:

   ```sh
   git clone https://github.com/serge-masiutin/opencode-session-mcp.git
   cd opencode-session-mcp
   npm ci
   npm run build
   ```

2. Добавьте **абсолютный путь** к клону в `plugins` глобального `~/.config/opencode/opencode.json`. Сохраните остальные поля и уже подключённые плагины:

   Добавьте пути в существующие массивы `plugins` и `instructions`, не заменяя другие пути. Если устанавливаете оба плагина, включите в каждый массив пути обоих.

   ```json
   {
     "$schema": "https://opencode.ai/config.json",
     "plugins": ["/absolute/path/to/opencode-session-mcp"],
     "instructions": ["/absolute/path/to/opencode-session-mcp/docs/agent-instructions.md"]
   }
   ```

   Глобальное подключение нужно, чтобы Desktop загрузил окно. Серверы по-прежнему задаются в `mcp.servers`; плагин не добавляет их адреса и credentials.

3. Выполните `/reload`, если команда ещё не появилась. В существующей сессии откройте `/mcp-session` и выберите сервер. До выбора серверы должны быть выключены; после подключения у выбранного сервера появится статус «Подключён».

Не добавляйте клон одновременно через `plugins` и `.opencode/plugins/`: достаточно одного подключения. Установка из npm не предусмотрена; репозиторий содержит исходники и lock-файл, GUI собирается локально.

### Инструкции для агента

Подключите [готовый файл инструкций](docs/agent-instructions.md) через `instructions`, как в примере установки. Другой вариант — скопировать его содержимое в ваш `~/.config/opencode/AGENTS.md` для всех проектов или в проектный `AGENTS.md`. Выберите один способ, чтобы не дублировать правила; сохраните уже существующие пути в `instructions`.

Если копируете правила в `AGENTS.md`, не добавляйте путь этого файла в `instructions`; если уже добавили — удалите только этот путь. Остальные пути и правила сохраните.

Плагин сам регистрирует `mcp_subagents` с описанием контракта и применяет права сессии. Файл инструкций объясняет агенту, когда просить пользователя включить сервер и как выбирать MCP перед делегированием. Одно подключение GUI не заменяет эти рабочие правила.

## Использование

Щелчок по строке или переключателю включает сервер в текущей сессии. Поиск учитывает имя и название; Enter переключает единственный найденный сервер. Список фиксирует порядок при открытии, чтобы строки не прыгали во время выбора. Окно закрывается Esc или крестиком.

- **«Ошибка подключения» → «Повторить».** Текст ошибки доступен во всплывающей подсказке.
- **«Нужен вход».** Если доступна кнопка «Войти», она открывает OAuth-страницу. Если интеграция требует форму, используйте встроенный `/mcp`; плагин покажет это ограничение ошибкой.
- **Сервер выключили во встроенном `/mcp`.** Плашка активной сессии пытается подключить его снова, пока он выбран в `/mcp-session`. Для выключения в сессии используйте именно `/mcp-session`.

### Сабагенты

Инструмент `mcp_subagents` доступен агенту, а не как slash-команда пользователя. Перед запуском сабагента агент выбирает только серверы, включённые в его собственной сессии. Выбор действует для следующих новых сабагентов до следующего вызова инструмента; права уже запущенных детей он не меняет.

Для разных наборов используйте последовательность «выбор → запуск», а не один параллельный батч. Пустой массив сбрасывает выбор. Сам выбор набора не запускает сабагента.

## Как устроена изоляция

`runtime.mjs` принудительно выключает невостребованные серверы через MCP transform и добавляет запреты на MCP-инструменты и ресурсы. Выбор пользователя сохраняется в `session.permissions`; явные правила сессии разрешают выбранные и запрещают остальные серверы, перекрывая прежние широкие разрешения. При расширении каталога плагин обновляет сохранённые правила. `rules.mjs` учитывает вложенные префиксы: `a` не открывает выключенный `a_b`, а разрешённый `a_b_c` остаётся доступным. Совпадающие нормализованные имена вроде `a.b` и `a_b`, имена с `*`/`?` и префиксы встроенных инструментов (`opencode`, `opencode_list`, `opencode_list_mcp`, `opencode_read`, `opencode_read_mcp`, `opencode_session`, `opencode_worktree`) отклоняются как ошибка конфигурации: их нельзя безопасно различить правилами инструментов. Другие имена с `opencode_`, например `opencode_console`, разрешены.

Это **фильтрация прав OpenCode, не файловая или сетевая песочница**. Плагин не скрывает credentials от других программ и не отменяет уже выполненные вызовы. Не используйте его как защиту от произвольного shell-кода агента. MCP-подключение и процесс остаются общими для сессий одной папки; разные worktree имеют отдельные подключения.

### Перезапуск и ограничения

- Выбор MCP хранится в правах сессии. После перезагрузки подключение восстанавливается при следующем промпте; до этого окно может показывать «Подключается…».
- Счётчик удержаний серверов хранится в памяти. После перезагрузки он собирается заново при промптах сессий, а не сканированием всей истории. Закрытие вкладки само по себе не выключает MCP: выключайте ненужные серверы явно.
- Набор для **следующих** сабагентов хранится в памяти и сбрасывается при перезагрузке.
- При удалении плагина его запреты больше не применяются, а проектный конфиг может снова подключить MCP. До удаления задайте `disabled: true` в нужных конфигах. Уже записанные разрешения сессий автоматически не удаляются.
- Статусы и начало OAuth проверяются через API OpenCode. Полный вход у конкретного провайдера зависит от его интеграции; плагин не хранит токены OAuth.

## Разработка и проверки

```sh
npm ci
npm test
npm run check
npm run build
```

Тесты правил и runtime не используют платные модели или внешние MCP. Для браузерной проверки реального компонента с тестовым host API запустите:

```sh
npm run test:gui
```

Откройте `http://127.0.0.1:4921/test/gui/index.html?theme=light`, затем `?theme=dark`. Проверьте колесо над именами серверов, неподвижность поиска, счётчик и переключение. Песочница намеренно блокирует wheel на уровне документа: обработчик списка должен оставить нативную прокрутку работающей. Это проверка компонента, не замена проверке установленного Desktop.

Состав и проверка установки из чистого клона описаны в [руководстве разработчика](docs/development.md).
